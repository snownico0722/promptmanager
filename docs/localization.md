# 中文界面与本地化维护

保留英文原文，简体中文由本地字典提供；不使用翻译服务，不增加运行时依赖。

## 实现约束

- `i18n-core.js` 统一负责 `auto / en / zh-CN`、`uiLanguage` 持久化、字典和订阅。`auto` 优先使用浏览器界面语言。原生扩展名称/描述仍由 Chrome `_locales` 按浏览器语言决定；工具栏标题会跟随应用设置。
- `i18n.js` 仅处理已注册的扩展界面。扩展页面注册自己的 document；内容脚本创建 `opm-root`、输入框选择器或提示条时显式注册。不会监听、翻译宿主网页，也不修改宿主 `<html lang>`。
- 提示词标题、正文、标签、标签建议、变量名和发布用户名用 `data-opm-user-content` 标记。用户文本使用 `textContent`，不作为 HTML 插入。输入框值始终不参与翻译。
- 文本与每个属性分别保留原文和上次渲染值；只更新发生变化的值。功能定位使用稳定 ID 或 `data-opm-action`，不依赖翻译后的 `aria-label`。
- 对话框在调用处使用 `OPMI18n.alert/confirm`。后台注入的原生输入对话框通过参数接收译文。不覆盖 `window.alert/confirm/prompt/fetch`。
- 右键菜单由 `service-worker.js` 独立负责，生成时选择语言并串行执行重建。保留原有批量修改的 200ms 防抖，但不再设置“稍后补翻译”的计时器。
- 更新日志由视图直接调用 `OPMChangelog.mount/unmount`。按语言缓存文件，过期请求不能覆盖新视图；不使用 DOM 观察器或特定版本号猜测语言。

## 文案约定

Prompt 译为“提示词”，Tag 译为“标签”，Hot corner 译为“右下角热区”。“社区提示词库”表示公开网站，而非本地文件目录。品牌名称保留原文。变量示例使用 `#name#`；当前解析器只接受英文字母、数字和下划线，不宣称支持中文变量名。

修改英文文案时同步更新 `i18n-core.js`，检查动态提示、无障碍属性和错误路径。现有 DOM 适配器是渐进接入方案，不代表未来新增节点自动具备正确的翻译语义。

## 验证

```sh
npm install --ignore-scripts
npm run test:i18n:unit
PUPPETEER_EXECUTABLE_PATH=/path/to/chrome npm run test:i18n:browser
```

浏览器测试执行实际页面和脚本，但通过模拟 Chrome 扩展 API 隔离账号、权限和存储；拦截外部请求，不访问真实社区服务。覆盖语言切换、原文恢复、用户文本保护、菜单生命周期、选中文字保存、日志加载，以及四个页面的中文显示和侧边栏编辑/复制。

这些测试不等于真实 Chrome/Edge 解压安装验收，也不覆盖所有第三方聊天网站的输入框适配。发布前仍应在实际扩展环境抽查权限弹窗、原生右键菜单、侧边栏和页面内面板。
